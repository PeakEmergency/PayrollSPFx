# Expense Report Submit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Submit to the Expense Report form: it locks the report, attaches the filled Excel form next to the receipts, fills the email columns and sets `Status` = `Queued` so the "Expense report email" flow sends it.

**Architecture:** The pure Excel fill and the email text sit beside their timesheet counterparts. `IReportService` gains four small item operations. A `submitReport` function runs the Pending → attach → Queued sequence and rolls back to draft on failure. The React form calls the existing save, then `submitReport`, and goes read-only whenever `status` is not blank.

**Tech Stack:** SPFx 1.24, React, TypeScript, ExcelJS (dynamic import), Jest via `heft test` on `lib-commonjs`.

**Spec:** `docs/superpowers/specs/2026-11-05-expense-report-submit-design.md`

## Global Constraints

- No Graph, no new API permissions. SharePoint REST only, through the existing `HttpTransport` / `SPHttpClient`.
- `src/expenseReport/` was copied from another repo: change only what the feature needs. Keep its strict payload codec unchanged; `status` lives in a list column, never in `Payload`.
- `Status` values exactly: blank (draft), `Pending`, `Queued`, `Sent`, `Email failed`.
- Recipient is the web part's existing `emailTo` property.
- Excel file name: `Expense Report - <NAME> - <fromISO>_<toISO> - <ID>.xlsx`.
- Subject: `Expense Report from <NAME> – <dd/mm/yy> to <dd/mm/yy>` (en dash, as in timesheets).
- Template file in the `Timesheet Templates` library: `Expense Report Template.xlsx`, sheet `Expense Report Template`.
- `npm test` must pass after every task. If it fails with `EPERM` on `jest-output`, run `rm -rf jest-output` and retry.

## Review Focus

1. Submit pressed with unsaved edits or pending receipts: both must be saved before the report goes `Pending`. Checked by hand in Task 5, step 6.
2. A submitted report saved from a second open tab must be rejected, not overwritten. Test in Task 3.
3. Failure while attaching or queueing must leave a draft (`Status` blank) with no half-made Excel attachment. Test in Task 4.
4. A report left `Pending` (browser closed) must finish via "Finish submitting" without needing its old ETag. Test in Task 4.
5. Names with an apostrophe (`O'CONNOR, KATHRYN (KATIE)`) in the attachment file name must upload and replace correctly. Test in Task 3.

### Task 4: `submitReport` sequence

**Files:**
- Create: `src/expenseReport/services/submitReport.ts`
- Test: `src/expenseReport/submit.test.ts`

**Interfaces:**
- Consumes: Task 1 `fillExpenseReport`, Task 2 `expenseFileName`/`expenseSubject`/`expenseBody`, Task 3 service methods.
- Produces:

```ts
export interface SubmitReportDeps {
  service: IReportService;
  loadTemplate(): Promise<ArrayBuffer>;
  emailTo: string;
  senderEmail: string;
  receiptCount: number;
  fill?: typeof fillExpenseReport; // tests replace it; defaults to fillExpenseReport
}
/** report must be saved (id and etag set) with status '' or 'Pending'. */
export async function submitReport(report: ExpenseReport, deps: SubmitReportDeps): Promise<void>;
```

Sequence: status `''` → `setStatus(id, 'Pending', report.etag)`; status `'Pending'` → skip that call; any other status → throw `ReportServiceError('This report has already been submitted.', 'conflict')`. Then `fill(await loadTemplate(), report)` → `attachFile(id, expenseFileName(report, id), bytes)` → `queueEmail(id, { to: emailTo, subject, body })`. If anything after Pending throws: `deleteAttachment` when `attachFile` succeeded, then `setStatus(id, '')`. Swallow errors from these two cleanup calls, then rethrow the original error with its message prefixed `Submitting failed; the report is still a draft. `.

  - `finishes a Pending report without its ETag`: report status `'Pending'` and `etag: undefined` → resolves, status `'Queued'`, no `setStatus('Pending')` call.
  - `returns to draft when the email columns fail`: `queueEmail` rejects → rejects with a message starting `Submitting failed; the report is still a draft.`, status `''`, Excel attachment gone.
  - `returns to draft when the template fails to load`: `loadTemplate` rejects → status `''`, `deleteAttachment` not called.
  - `refuses a submitted report`: status `'Sent'` → rejects `{ kind: 'conflict' }`, `setStatus` not called.
